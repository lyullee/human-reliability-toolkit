# Development plan

## Operational extension milestone

The version 0.3 requirement set covers G01-G12. Build executable action and causal
semantics first, then risk orchestration, communication/work control, operational
evidence and intervention comparison. Add process feedback, progress/deadline
checks, information/diagnosis, sparse inference, procedure/assurance lifecycle and
selected reference workflows on those contracts.

The completed implementation scope and acceptance cases are maintained in
`research/extension_implementation.json` and `research/extension_validation.json`.
[Operational extensions](OPERATIONAL_EXTENSIONS.md) documents the public parameters;
[Extension validation](EXTENSION_VALIDATION.md) records verification. Field
qualification, unavailable source data and receiving-system changes remain explicit
research/integration conditions rather than fabricated software evidence.

The objective is a reusable human-reliability library with explicit assumptions,
customizable data and coefficients, reproducible examples and typed integration
boundaries. Public process signals establish context and software integration;
only genuine task opportunities and observed responses can calibrate human error.

## Scope and prioritization

Model operational obstacles, observation, rule execution, diagnosis, planning,
management conditions, communication, procedure quality, latent hazards, error
recovery, automation and collaboration as composable task/context mechanisms.
General organizational concepts do not have universal probability multipliers.
Implement evidence-backed mathematics and configurable qualitative workflows;
label coefficient-dependent named methods and research extensions precisely.

Prefer current maintained numerical, survival and sensitivity libraries when they
add verified capability. A newer method is not automatically better calibrated for
a different process or workforce. Keep empirical estimation, cognition-informed
event decomposition and dependence-aware dynamic scenarios central.

## Public source boundary

This folder is the prospective repository. Parent-folder analysis and private
research materials are outside it. Publish original code and explanations, method
references, dependency notices, dataset metadata and reacquisition instructions.
Do not ship third-party source documents, raw external datasets, copied prose or table layouts,
credentials or workstation-specific paths. Record verified rights and unresolved
conditions; do not describe a technical packaging audit as a legal guarantee.
Selected numeric facts and permitted aggregates may be included only with source
rights, independent labels and the attribution in `DATA_LICENSES.md`.

## Evidence extension: version 0.2

The extension reviewed 18 human-error evidence candidates, acquired 13 pinned
source assets and curated seven selected sources into 1,334 typed records. The
acceptance gates are preserved provenance, observed-versus-method separation,
application review, explicit priors/exposure, reference-profile safeguards,
English handoff documentation and a clean offline core-wheel installation.
GitHub publication follows local verification and distribution inspection.
